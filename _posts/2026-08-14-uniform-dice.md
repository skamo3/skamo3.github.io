6면체 주사위 하나로 1부터 18까지의 수를 만들어야 한다. 조건은 하나, 모든 수가 같은 확률로 나와야 한다.

## 흔한 오답

### 주사위 3개의 합

범위만 보면 3부터 18까지라 얼추 맞는 것처럼 보인다. 하지만 분포가 균등하지 않다. 216가지 경우를 전부 세어보면 이렇다.

| 합 | 경우의 수 | 합 | 경우의 수 |
|---|---|---|---|
| 3 | 1 | 11 | 27 |
| 4 | 3 | 12 | 25 |
| 5 | 6 | 13 | 21 |
| 6 | 10 | 14 | 15 |
| 7 | 15 | 15 | 10 |
| 8 | 21 | 16 | 6 |
| 9 | 25 | 17 | 3 |
| 10 | 27 | 18 | 1 |

10과 11이 27가지, 3과 18이 1가지다. **27배 차이**다.

가운데로 몰리는 이유는 만들 수 있는 조합의 수가 다르기 때문이다. 3은 `(1,1,1)` 하나뿐이지만 10은 `(1,3,6)` `(2,4,4)` `(3,3,4)`처럼 여러 갈래가 있다. 독립 시행의 합은 항상 이렇게 종 모양이 된다.

애초에 1과 2는 나올 수도 없다.

### 한 번 굴려 3을 곱하기

3, 6, 9, 12, 15, 18. 여섯 개만 나온다. 나머지 열두 개는 영영 나오지 않는다.

## 균등 분포의 조건

두 오답이 같은 지점에서 어긋난다. 필요한 것은 두 가지다.

- 같은 확률의 결과가 몇 가지인지
- 그 개수를 목표 개수로 정확히 나눌 수 있는지

주사위를 k번 굴리면 6<sup>k</sup>가지 결과가 나오고, 이들은 전부 같은 확률이다. 이 6<sup>k</sup>를 18로 나누어떨어지게 만들고 각 목표값에 같은 개수씩 배정하면 균등해진다.

6은 18보다 작아서 안 되고, 6<sup>2</sup> = 36은 18의 정확히 2배다. **두 번 굴리면 된다.**

## 두 번 굴려 18가지 만들기

### 구간과 값으로 나누기

18을 3 × 6으로 분해한다.

첫 굴림으로 세 구간 중 하나를 고른다. 1과 2는 0구간, 3과 4는 1구간, 5와 6은 2구간이다. 각 구간에 눈이 두 개씩 배정되므로 확률은 정확히 1/3이다.

둘째 굴림으로 1~6을 얻는다. 각각 1/6이다.

두 굴림은 서로 영향을 주지 않으므로 (구간, 값) 조합은 3 × 6 = 18가지이고, 각 조합의 확률은 1/3 × 1/6 = 1/18이다.

<pre class="mermaid">
flowchart TD
    R1["1번째 굴림<br/>1~6"] --> B["구간 0 / 1 / 2<br/>각 1/3"]
    R2["2번째 굴림<br/>1~6"] --> V["값 1~6<br/>각 1/6"]
    B --> RES["구간 × 6 + 값<br/>1~18, 각 1/18"]
    V --> RES
</pre>

```cpp
int Roll18()
{
    int band = (D6() - 1) / 2;   // 1,2 -> 0 / 3,4 -> 1 / 5,6 -> 2
    return band * 6 + D6();      // 1~18
}
```

### 36가지를 2개씩 묶기

두 굴림 결과를 좌표처럼 펼치면 36가지가 나온다. 36 = 18 × 2이므로 두 개씩 묶어 하나의 값에 배정해도 된다.

```cpp
int Roll18()
{
    int idx = (D6() - 1) * 6 + (D6() - 1);  // 0~35, 각 1/36
    return idx / 2 + 1;                      // 1~18, 각 2/36
}
```

36가지를 전부 열거해 확인하면 두 방법 모두 각 값이 정확히 두 번씩 나온다.

```
값 : 구간분해 / 2개씩묶기
 1 :   2      /   2
 2 :   2      /   2
 3 :   2      /   2
...
18 :   2      /   2
```

## 나누어떨어지지 않을 때

1~7을 만들어야 한다면 방법이 통하지 않는다. 36을 7로 나누면 1이 남고, 세 번 굴려 216가지를 만들어도 6이 남는다. 6<sup>k</sup>의 소인수는 2와 3뿐이라 7로는 영원히 나누어떨어지지 않는다.

### 거부 샘플링

나누어떨어지는 만큼만 쓰고 나머지는 버린다.

36가지 중 0~34, 35가지만 사용한다. 35는 7 × 5라 다섯 개씩 묶으면 일곱 개 값이 나온다. 35가 나오면 결과를 버리고 처음부터 다시 굴린다.

<pre class="mermaid">
flowchart TD
    S["두 번 굴려 0~35"] --> C{"35인가"}
    C -->|예| S
    C -->|아니오| R["0~34를 5로 나누기<br/>1~7, 각 5/35"]
</pre>

```cpp
int Roll7()
{
    while (true)
    {
        int idx = (D6() - 1) * 6 + (D6() - 1);  // 0~35
        if (idx < 35)
            return idx / 5 + 1;                  // 1~7
        // 35가 나오면 버리고 다시 굴린다
    }
}
```
{: .no-collapse}

버린 뒤 다시 굴린 결과는 처음과 똑같은 조건에서 나온다. 남은 35가지 사이의 상대 확률이 그대로라 균등성이 깨지지 않는다.

### 몇 번 굴리게 되나

한 번의 시도가 성공할 확률은 35/36이다. 성공까지 걸리는 시도 횟수의 기댓값은 36/35이고, 한 시도에 두 번 굴리므로 평균 굴림 횟수는 72/35, 약 2.06번이다.

버리는 경우가 있어도 평균 비용은 2번에서 거의 늘지 않는다. 대신 최악의 경우에는 상한이 없다. 운이 나쁘면 35가 계속 나올 수 있다.

## rand() % n도 같은 문제다

주사위 이야기로만 끝나지 않는다.

```cpp
int value = rand() % 18 + 1;   // 균등하지 않다
```

`rand()`가 0부터 `RAND_MAX`까지 완벽하게 균등하다고 해도, 전체 개수가 18로 나누어떨어지지 않으면 앞쪽 값들에 하나씩 더 배정된다. 나머지를 버리지 않고 그냥 접어버린 셈이다.

MSVC와 MinGW 모두 `RAND_MAX`가 32767이다. 32768가지를 18로 나누면 8이 남으므로, 앞의 여덟 개 값만 한 번씩 더 가져간다.

```
RAND_MAX = 32767
[rand() % 18 + 1] 전체 32768가지
   1 : 1821
   ...
   8 : 1821
   9 : 1820
   ...
  18 : 1820
```
{: .no-collapse}

차이가 0.05% 수준이라 주사위 3개 합처럼 눈에 띄지는 않는다. 뽑는 범위가 커질수록 편향도 같이 커진다.

C++11부터는 직접 처리할 필요가 없다.

```cpp
std::mt19937 gen(std::random_device{}());
std::uniform_int_distribution<int> dist(1, 18);
int value = dist(gen);
```

`uniform_int_distribution`이 이 편향을 처리해준다.

## 정리

- 균등 분포를 만들려면 같은 확률의 결과 공간을 만들고, 그 개수를 목표 개수로 정확히 나눠야 한다
- 독립 시행의 합은 가운데로 몰린다. 6면체 세 개의 합은 10이 3보다 27배 자주 나온다
- 18은 36의 약수라 두 번 굴리면 나머지 없이 나뉜다
- 나누어떨어지지 않으면 남는 부분을 버리고 다시 굴린다. 평균 비용은 거의 늘지 않지만 최악의 경우 상한이 없다
- `rand() % n`이 균등하지 않은 이유도 같다. 나머지를 버리는 대신 접어버리기 때문이다
