# Ch2 개념1 · 기본 조명 — Directional Light와 법선 보정

> Ch1에서 미뤄둔 문제를 여기서 갚는다. "정점을 옮기면 법선이 어긋난다"고 예고했던 그 문제를, 지형에 실제로 빛을 비춰서 눈으로 확인하고 고친다.
>
> 쉐이딩 모델 비교(Lambert/Phong/PBR)와 glTF 레퍼런스 모델은 별도 월드([ch2-pbr.js](../worlds/ch2-pbr.js), [이론 노트](ch2-pbr.lesson.md))로 분리했다. 랜드스케이프를 멀리서 보는 것과 재질을 가까이서 비교하는 것은 카메라 언어가 달라, 한 화면에 있으면 스케일 감각이 어긋나기 때문이다.

## 이 개념에서 배우는 것

- 왜 조명 계산에 법선(normal)이 필요한가
- 정점을 변위(displace)하면 원래 법선이 왜 틀려지는가, 그리고 왜 다시 계산해야 하는가
- 가장 단순한 조명 모델 — Lambert diffuse (`N·L`)

## 이론

물체의 한 점이 얼마나 밝은지는 그 점의 **표면이 빛을 향해 얼마나 정면으로 서 있는가**로 정해진다. 정면으로 설수록 밝고, 비스듬할수록 어둡고, 빛의 반대쪽을 향하면 안 보인다. 이 "표면이 향한 방향"이 **법선(normal)**이고, "빛으로 가는 방향"이 **L**이다. 둘 사이의 각도가 작을수록(내적이 클수록) 밝다.

```
diffuse = max(N · L, 0)
```

이게 가장 단순한 조명 모델인 **Lambert 반사**다. 표면이 빛을 사방으로 고르게 반사한다고 가정한다(무광 벽지 같은 재질). 실제 재질(금속, 플라스틱)은 여기에 반사광(specular)과 재질 파라미터(금속성·거칠기)가 더 필요한데, 그건 별도 월드([ch2-pbr.lesson.md](ch2-pbr.lesson.md))에서 Lambert → Phong → PBR 순서로 다룬다. 지금은 diffuse 하나로 시작한다.

## Ch1에서 예고했던 문제

Ch1의 지형은 평면 정점을 heightmap 높이로 밀어 만들었다. 그런데 평면 원본의 법선은 **전부 위(로컬 +Z)를 향한 채 고정**돼 있다. 정점을 밀어서 언덕이 생겨도, 법선을 다시 계산하지 않으면 언덕 경사면도 "평평한 곳"인 것처럼 조명 계산을 하게 된다. 그러면 경사면인데 정면광을 받은 것처럼 밝거나, 반대로 능선인데 그림자가 진다 — 지형의 굴곡과 음영이 어긋난다.

해법은 변위 후 **각 정점 주변 삼각형들의 기울기로 법선을 다시 계산**하는 것이다. three.js는 `geometry.computeVertexNormals()`로 이를 자동화한다.

## 이론 → 코드 매핑

`worlds/ch2-lighting.js`에서

- `aFlatNormal` attribute = 변위 **전** 평면의 법선. 전부 로컬 `(0, 0, 1)`로 고정 — "법선을 안 고친 경우"를 재현하는 값
- `normal` attribute = `computeVertexNormals()`로 변위 **후** 다시 계산한 진짜 법선 — "법선을 고친 경우"
- `uUseCorrectNormal` uniform + GUI 체크박스 = 이 둘을 실시간으로 바꿔 끼워 차이를 비교
- `uLightDir` = 태양이 있는 방향(표면→광원, 이미 정규화된 L). GUI의 고도·방위각 슬라이더로 조절
- fragment shader의 TODO 한 줄 = Lambert 공식 `max(dot(N, L), 0)`

## 관찰 포인트

1. **"재계산된 법선 사용"을 끈 상태**로 태양 고도를 낮게 두고 지형을 돌려본다 — 경사면과 능선의 음영이 실제 굴곡과 안 맞는 걸 확인한다 (평평한 판에 조명 준 것처럼 보임)
2. **다시 켠다** — 같은 지형인데 경사면은 어둡고 능선은 밝은, 굴곡과 일치하는 음영이 나온다
3. 태양 고도·방위각을 돌리면서 음영이 실시간으로 바뀌는 것 확인 (해가 지형을 도는 것과 같은 효과)
4. 환경광(ambient)을 0으로 내리면 빛 반대편이 완전히 검게 죽는 것도 확인 — 실제 장면엔 항상 약한 ambient가 필요한 이유

## 엔진 매핑

- **UE**: Directional Light 액터, Material의 Lit 셰이딩 모델(WorldNormal 입력), Lightmass가 정적 GI를 굽기 전 단계
- **Unity**: Light 컴포넌트(Directional), Lit 셰이더의 기본 diffuse 항, `dot(normalWS, lightDir)` 패턴
- **D3D**: 픽셀 셰이더에서 `saturate(dot(N, L))`, 상수 버퍼로 넘긴 조명 방향
